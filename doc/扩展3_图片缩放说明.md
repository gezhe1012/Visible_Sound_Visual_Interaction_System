# 扩展要求3：不同分辨率BMP与双线性缩放

本版在读取TF卡时直接把源图缩放成640×480，然后写入原来的SDRAM双帧缓存。HDMI时序、OSD、转场和音频继续使用原通路。扩展3无需新增板载按键或管脚。

## 支持范围与显示方式

- 24-bit、BI_RGB（不压缩）BMP；DIB信息头大小40～124字节。
- 原图宽、高分别为1～2048像素，支持放大和缩小。
- 正高度BMP按自底向上存储；负高度BMP按自顶向下存储，两者都正确显示。
- 支持非54字节像素偏移（最大1 MiB），以及BMP每行4字节对齐补齐。
- 输出固定为640×480，采用双线性插值并铺满屏幕。非4:3素材会改变宽高比，本版未增加等比例留黑边模式。
- 保留参考工程的物理扇区扫描方式：BMP文件头位于扇区边界，且文件数据需要占用连续扇区；本版没有增加FAT簇链/碎片文件解析。准备TF卡时应使用整理后的卡并验证实际图片读取情况。
- 最多扫描四张合法BMP；32位BMP、压缩BMP、超出范围或声明长度不足的BMP不会进入写帧流程。

## 算法

横坐标使用 `sx = x*(W-1)/639`，纵坐标使用 `sy = y*(H-1)/479`。这使输出首尾像素精确对应源图边界，640×480输入逐像素保持一致。

坐标生成采用整数余数累加：每前进一个输出像素，横向余数加 `W-1`；当余数达到639，减去639并推进源像素整数坐标。纵向采用相同方法，以479为分母。

横纵小数权重各为8位，通过8周期逐位除法计算 `floor(余数*256/分母)`。插值采用：

```text
h0 = round((p00*(256-fx) + p10*fx)/256)
h1 = round((p01*(256-fx) + p11*fx)/256)
out = round((h0*(256-fy) + h1*fy)/256)
```

硬件共享RGB三个通道的乘法器，依次完成两次水平插值和一次垂直插值。减法、乘法、加法分级寄存，降低100 MHz域的组合路径长度。两个2048×24-bit同步行缓存保存相邻源行，输出完整一行后才移动纵坐标。缩放只在加载图片时发生，不增加每次HDMI刷新的SDRAM读带宽。

## FIFO与帧提交

插值模块在输出像素前检查写时钟域的FIFO占用，达到480项时暂停，给512深度FIFO保留32项余量。FIFO内同步后的写侧计数生成反压，避免放大图片时连续输出导致溢出。

源图处理结束与SDRAM整帧写入完成分别锁存。二者均完成才启动已有转场，避免完成事件先后顺序造成漏提交。文件头拒绝或无进展超时将撤销当前加载，不提交不完整帧。

## 板级验证

1. 使用 `tests/generate_scaler_assets.py` 生成四张不同原始分辨率的BMP。生成器只产生测试图案，不预先缩放图片。
2. 将 `doc/scaler_test_images` 中四张图片用于TF卡测试，先移除用于测试的旧图数据，避免原始扇区扫描命中旧图片。
3. 下载本次构建的 `.bit` 到HX4S20C，连接HDMI_B。
4. 检查每张图的白色边框、红色横向渐变、绿色纵向渐变和蓝色棋盘。绿色应从上方暗到下方亮，边框应完整；竖图会按当前策略拉伸铺满。
5. 按KEY1切换四张图片，检查OSD与淡入淡出；按KEY2检查连续轮播并确认HDMI音频持续播放。
6. 板级验证后再固化Flash并进行断电重启测试。
